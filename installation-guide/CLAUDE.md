# Installation runbook for Claude Code

> Pre človeka: toto je presný postup pre AI agenta (Claude Code). Ľudský návod je v [README.md](README.md). Agent komunikuje s používateľom po slovensky.

Goal: install and run the **Náklady zákaziek** server (Docker Compose: `db`, `app`, `scheduler`, optionally `cloudflared` or `caddy`) on the user's machine or a cloud VM, verify it, and hand the user a working URL and login. The human guide `installation-guide/README.md` is the source of truth for the steps; this file adds the decision logic, exact commands and acceptance checks.

## Hard rules

1. **Never run `docker compose down -v`, `docker volume rm` or delete `backups/`.** Volumes `db_data` and `app_files` hold all business data. Use `docker compose stop` / `restart` / `up -d`.
2. **Never commit or display `.env`.** Do not print `SECRET_KEY`, `POSTGRES_PASSWORD`, API keys or tokens. The only secret you may show is a *generated* admin password, once, in your final message.
3. **Never invent credentials** (API keys, OAuth client, Cloudflare token, domain). Ask the user. Missing optional integrations are fine; report them as "not configured".
4. **Never expose port 8000 to the internet without TLS.** Remote access = Cloudflare Tunnel (path B) or Caddy with a domain (path C). Do not suggest router port-forwarding of 8000.
5. Do not change `POSTGRES_PASSWORD` or `SECRET_KEY` after the first start (DB auth breaks / everyone gets logged out).
6. All scripts are idempotent. Re-running is safe; `setup-env` never overwrites an existing `.env` unless `--force` (do not use `--force` without the user's consent).
7. Run commands from the repository root. Acceptance = `installation-guide/scripts/check-install.sh` exits `0`.
8. Ask before anything needing admin rights on the user's own computer (installing software, firewall rules, scheduled tasks).

## Procedure

### Step 1 – detect the environment
```bash
uname -s 2>/dev/null; cat /etc/os-release 2>/dev/null | head -3; docker --version; docker compose version; git --version
```
- Windows: you are likely in PowerShell or Git Bash. Docker Desktop must be installed by the user (GUI installer, WSL2, reboot); you may run `winget install -e --id Docker.DockerDesktop` and `winget install -e --id Git.Git` with consent, then ask the user to start Docker Desktop and enable "Start when you sign in". Run `.sh` scripts via Git Bash (`"C:\Program Files\Git\bin\bash.exe" -lc "…"`).
- macOS: Docker Desktop (`brew install --cask docker` if Homebrew exists), user starts it once.
- Ubuntu/Debian (incl. cloud VM, WSL Ubuntu): `sudo ./installation-guide/scripts/install-docker-ubuntu.sh`, then `newgrp docker` or prefix docker with `sudo` for this session.

**Check:** `docker info >/dev/null && docker compose version` succeeds.

### Step 2 – get the code
If not already inside a clone:
```bash
git clone https://github.com/3perko/New-test-repository-100eur.git naklady && cd naklady && git checkout claude/trusting-babbage-61jjql
```
(The application lives on branch `claude/trusting-babbage-61jjql` until it is merged into the default branch; if `git branch -r` shows it merged, stay on the default branch.)

**Check:** files `docker-compose.yml`, `Dockerfile`, `.env.example` exist.

### Step 3 – create `.env`
Path A:
```bash
./installation-guide/scripts/setup-env.sh --non-interactive --admin-email "$EMAIL" [--admin-password "$PWD"] [--anthropic-key "$KEY"] [--google-id "$GID" --google-secret "$GSECRET"]
```
Path B (add): `--base-url "https://$HOST" --port 127.0.0.1:8000 --tunnel-token "$TOKEN"` (keep `--port 8000` if the user also wants LAN access).
Path C (add): `--base-url "https://$HOST" --port 127.0.0.1:8000 --domain "$HOST"`.
Windows PowerShell equivalent: `powershell -ExecutionPolicy Bypass -File .\installation-guide\scripts\setup-env.ps1 -AdminEmail … [-AdminPassword …] [-BaseUrl …] [-Port …] [-TunnelToken …] [-Domain …]`.

Capture the printed admin password if it was generated. **Check:** `.env` exists; `check-install.sh` section "Konfigurácia" has no `CHYBA`.

### Step 4 – build and start
| Path | Command |
| --- | --- |
| A | `docker compose up -d --build` |
| B | `docker compose -f docker-compose.yml -f docker-compose.tunnel.yml up -d --build` |
| C | `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build` (DNS A record must already point to the VM; ports 80/443 open: `sudo ufw allow OpenSSH && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp && sudo ufw --force enable`) |

First build takes 5–10 min. Then wait until healthy:
```bash
for i in $(seq 1 30); do curl -fsS http://localhost:${PORT:-8000}/api/health && break; sleep 5; done
```
(`PORT` = the number part of `APP_PORT`.)

### Step 5 – verify (acceptance)
```bash
./installation-guide/scripts/check-install.sh --login "$EMAIL" "$PWD"
```
Must end with `VÝSLEDOK: OK` and exit code `0`. For B/C also run with `--url "https://$HOST"` (TLS issuance by Caddy can take ~1 min on first start; retry).
Optional demo data (only if the user asked): `docker compose exec app python -m app.cli seed-demo`.

### Step 6 – operations setup (ask first)
- Daily backup: Linux/macOS cron `15 2 * * * <repo>/deploy/backup.sh >> <repo>/backups/backup.log 2>&1`; Windows `Register-ScheduledTask` command from README §8. Run `./deploy/backup.sh` once and confirm files appear in `backups/`.
- Windows LAN access (path A): firewall rule from README §6a (admin PowerShell).
- Remind the user about sleep settings (own PC) and off-machine copies of `backups/`.

### Step 7 – report to the user (Slovak)
Include: URL(s) (local, LAN IP, public), admin login (+ generated password if any), which integrations are configured / missing and the README section to finish them, how to back up, update (`installation-guide/scripts/update.sh [-f <override>]`) and check (`check-install.sh`). Mention Google "Testing" mode 7-day token expiry if Google was configured.

## Migration own PC → cloud
1. Source: `./deploy/backup.sh` → take newest `backups/db-*.dump` and `backups/files-*.tar.gz`.
2. Target VM: Steps 1–3 (path C), copy the two files into `<repo>/backups/` (`scp`), then:
   `docker compose -f docker-compose.yml -f docker-compose.prod.yml build` →
   `./installation-guide/scripts/restore.sh backups/db-….dump backups/files-….tar.gz --yes` (only after the user confirmed overwriting) →
   `docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d` → Step 5 with `--url https://$HOST`.
3. Ask the user to add the new Google redirect URI and reconnect Google; stop the old instance (`docker compose stop`) so only one scheduler processes inboxes.

## Troubleshooting map
| Symptom | Diagnose | Fix |
| --- | --- | --- |
| Pull fails `429 Too Many Requests` (Docker Hub) | anonymous rate limit | wait, or `docker login`; as a last resort pull `mirror.gcr.io/library/<image>` and `docker tag` it to the original name (`postgres:16-alpine`, `node:22-alpine`, `python:3.12-slim`), then build with `--pull=false` |
| `apt-get` fails inside `docker build` | no outbound HTTP from build containers (corporate proxy) | pass proxy build args (`--build-arg HTTPS_PROXY=… --network host`) or fix network; do not remove `fonts-dejavu-core` from the Dockerfile (PDF diacritics) |
| Port in use | `ss -ltnp \| grep 8000` / `lsof -i :8000` / `netstat -ano \| findstr 8000` | set `APP_PORT=8080` in `.env`, `docker compose up -d` |
| `app` restarting | `docker compose logs app --tail 100` | usually DB auth (changed `POSTGRES_PASSWORD`) or bad `.env` line |
| Login fails | admin only bootstraps when no user exists | `docker compose exec app python -m app.cli create-admin --email … --password …` |
| Logged out immediately on http | `COOKIE_SECURE=true` without TLS | set `false` for plain http |
| Caddy no certificate | `docker compose logs caddy` | DNS A record, ports 80/443 open, `DOMAIN` set |
| Tunnel 502/1033 | `docker compose logs cloudflared` | public hostname service must be `http://app:8000`; token correct |
| `.sh` fails on Windows with `\r` | CRLF checkout | `git config core.autocrlf false && git checkout -- .` |

## Facts you may need
- Health: `GET /api/health` → `{"ok":true}`; UI title `Náklady zákaziek`; login `POST /api/auth/login` (needs header `X-Requested-With: app`).
- Migrations run automatically on `app` start (`alembic upgrade head`).
- Scheduler: inbox daily at parameter `inbox_schedule_time` (default 20:00 Europe/Bratislava).
- Data: volumes `<project>_db_data`, `<project>_app_files`; files at `/app/data/files` in the container.
- CLI: `python -m app.cli create-admin | seed-demo | run-inbox` (run via `docker compose exec app …`).
